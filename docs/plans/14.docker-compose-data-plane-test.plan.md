# Docker Compose 数据面测试方案

## 目标

在隔离的 Docker bridge 网络中验证真实 IPVS NAT 流量，而不只验证
IPVS/iptables 规则是否存在。测试从独立客户端容器访问 VIP，并覆盖：

- IPVS `rr` 调度会把新 TCP 连接转发给两个后端
- FullNAT SNAT 后端实际观察到的来源地址是 VIP
- HTTP 健康检查失败会摘除后端，恢复后会重新加入
- `/ready`、`/health` 和 `/metrics` 管理接口可用

## 拓扑

```
verifier 172.30.0.20
          |
          v
ezlb/VIP 172.30.0.10:8080 -- IPVS NAT + SNAT --> backend-a 172.30.0.11:8080
                                      \--------> backend-b 172.30.0.12:8080
```

所有容器都位于 `172.30.0.0/24` 的临时 bridge 网络；不暴露主机端口。
只有 `ezlb` 服务拥有特权和 `/lib/modules` 只读挂载。其入口在自身网络
命名空间启用 `ip_forward`、`ip_vs conntrack` 并加载需要的 IPVS 模块。

## 执行与判定

运行：

```bash
make test-compose
```

Compose 以 `verifier` 的退出码作为结果，并无论通过或失败都删除容器和
网络。验证器依次断言：

1. `ezlb` 数据面已 reconcile，`/ready` 返回 200，两个 `/healthz` 探针为健康。
2. 经 VIP 的 12 个禁用 keep-alive 的 HTTP 请求均成功，且响应来自两个后端；
   后端报告的客户端 IP 是 `172.30.0.10`，证明 FullNAT 的 SNAT 路径生效。
3. `/metrics` 出现 `ezlb_service_connections_total` 的 `web` 标签序列。
4. 将 backend-b 的测试健康端点切为 503；`/health` 报告其不健康，随后 8 个
   新连接都只能到达 backend-a。
5. 恢复 backend-b；健康状态重新为真，并再次观察到两个后端收到 VIP 流量。

该测试既不复用主机网络，也不清理主机 IPVS 表；测试结束时由 `ezlb`
优雅退出清理其私有网络命名空间里的规则，Compose 再销毁整个网络。
