# Prometheus 监控指标实现

## 目标

为 ezlb 提供 Prometheus 监控指标支持：

- 复用 admin 端口暴露 `/metrics`，不引入额外监听端口
- 指标类型只用 Counter / Gauge，避免 Histogram 的成本与心智负担
- 数据来源是内核 IPVS 的累计计数器（cumulative counters），由进程内采集器按周期算 delta 后 `Add` 到 Prometheus Counter，避免直接 `Set` 累计值导致的双重累加

## 指标列表

### Service 级（标签：`service`, `listen`, `protocol`）

| 指标名 | 类型 | 说明 |
|--------|------|------|
| `ezlb_service_connections_total`   | Counter | 累计连接数 |
| `ezlb_service_bytes_in_total`      | Counter | 入向字节数 |
| `ezlb_service_bytes_out_total`     | Counter | 出向字节数 |
| `ezlb_service_packets_in_total`    | Counter | 入向包数 |
| `ezlb_service_packets_out_total`   | Counter | 出向包数 |

### Backend 级（标签：`service`, `backend`, `protocol`）

| 指标名 | 类型 | 说明 |
|--------|------|------|
| `ezlb_backend_connections_total`     | Counter | 后端累计连接数 |
| `ezlb_backend_bytes_in_total`        | Counter | 后端入向字节数 |
| `ezlb_backend_bytes_out_total`       | Counter | 后端出向字节数 |
| `ezlb_backend_packets_in_total`      | Counter | 后端入向包数 |
| `ezlb_backend_packets_out_total`     | Counter | 后端出向包数 |
| `ezlb_backend_active_connections`    | Gauge   | 后端活跃连接数（IPVS `ActConns`） |
| `ezlb_backend_inactive_connections`  | Gauge   | 后端非活跃连接数（IPVS `InActConns`） |

### Backend 健康（标签：`service`, `backend`）

| 指标名 | 类型 | 说明 |
|--------|------|------|
| `ezlb_backend_health_status` | Gauge | `1`=healthy, `0`=unhealthy；由 `server.Server.updateHealthMetrics()` 在健康状态变更时写入 |

### 控制面（无标签）

| 指标名 | 类型 | 说明 |
|--------|------|------|
| `ezlb_config_reload_total`     | Counter | 配置成功重载次数（由 `Server.Run()` 中注册的 `configMgr.SetOnReloadCallback` 触发） |
| `ezlb_reconcile_errors_total`  | Counter | Reconcile 错误次数（由 `lvs.Reconciler.Reconcile()` 在出错路径中累加） |

> **注意**：控制面 Counter 在生命周期事件（reload / reconcile error）发生时直接 `Inc()`，不经过 delta 机制；只有"映射 IPVS 累计计数"的指标走采集器 + delta 路径。

## 配置

```yaml
global:
  admin_address: "127.0.0.1:9095"   # admin HTTP 监听地址；为空则 admin 与 /metrics 一并禁用
  metrics_enabled: true             # 是否注册 /metrics endpoint（默认 true）
  metrics_path: "/metrics"          # /metrics 路径（默认 /metrics）
  metrics_interval: 15s             # Prometheus 采集周期，最小 5s，默认 15s
```

字段对应代码：

- `global.admin_address` → `config.GlobalConfig.AdminAddress`
- `global.metrics_enabled` → `config.GlobalConfig.MetricsEnabled` (`*bool`，默认 true)
- `global.metrics_path` → `config.GlobalConfig.MetricsPath` (默认 `/metrics`，通过 `GetMetricsPath()`)
- `global.metrics_interval` → `config.GlobalConfig.MetricsInterval` (默认 `15s`，下界 `5s`，通过 `GetMetricsInterval()`)

| 模块 | 文件 | 职责 |
|------|------|------|
| 指标定义 | `pkg/metrics/metrics.go` | 注册 CounterVec / GaugeVec、提供 `AddServiceTraffic` / `AddBackendTraffic` (delta 语义，含 packets)、`SetBackendConnections` / `SetBackendHealth` (gauge 语义)、`IncConfigReload` / `IncReconcileErrors`、`DeleteServiceMetrics` / `DeleteBackendMetrics` / `DeleteBackendHealthMetrics` |
| 采集 | `pkg/trafficmetrics/collector.go` | `Collector` 持有 `prev *TrafficSnapshot`、`run()` 周期循环、`collect()` 拉快照→算 delta→推 Prometheus、`UpdateConfig()` 支持配置热更 |
| 数据模型 | `pkg/trafficmetrics/models.go` | `ServiceTrafficStats` / `BackendTrafficStats` / `TrafficSnapshot` / `LVSStatsProvider` 接口（单方法 `AllStats()`） |
| IPVS 适配 | `pkg/trafficmetrics/lvs_stats_adapter.go` | 把 `lvs.Manager.GetServices/GetDestinations` 适配成 `LVSStatsProvider`，单次 `GetServices()` 同时采集 service 和 backend 统计，单 service `GetDestinations` 失败时 skip-and-log |
| HTTP 暴露 | `pkg/admin/server.go` | `metricsEnabled` 时挂载 `promhttp.Handler()` 到 `metricsPath` |
| 装配 | `pkg/server/server.go` | `syncTrafficCollector()` daemon 模式下按 `IsMetricsEnabled()` 起停 collector（支持热加载动态停止）；`initAdminServer()` 创建 admin server；`updateHealthMetrics()` 响应健康状态变更并清理残留指标 |
| Reconcile 错误 | `pkg/lvs/reconciler.go` | `Reconcile()` 出错时调用 `metrics.IncReconcileErrors()`；删除 service/backend 时调用 `DeleteServiceMetrics` / `DeleteBackendMetrics` 清理指标 |

## 关键设计决策

### 1. Counter 用 Add(delta)，不用 Set(累计值)

IPVS 暴露的是**累计**计数器；Prometheus Counter 也是累计型。如果直接 `Set(curr)` 会失败编译（Counter 没有 Set），如果改用 `Counter.Add(curr)` 则**每个采集周期都会把累计值再加一次**，导致指标快速膨胀。

正确做法：进程内维护 `prev` 快照，每周期 `Add(curr - prev)`。

```go
// pkg/trafficmetrics/collector.go
func counterDelta(curr, prev uint64) uint64 {
    if curr >= prev {
        return curr - prev
    }
    return curr // counter reset (IPVS 规则重建 / 主机重启)，按 curr 进位
}
```

`prev == nil`（首次采集）时，`prevStats` 为零值结构体，delta 等于 curr 本身——这是正确的：从 collector 启动开始计的累计量。

### 2. Counter reset 处理

IPVS 服务被删除重建（reconcile 路径）、`ipvsadm --clear`、主机重启都会让累计值倒退。`counterDelta` 检测 `curr < prev`，把 `curr` 直接当作本周期增量，**避免传 0 或负值**给 Prometheus。

### 3. Gauge 用 Set，不算 delta

`active_connections` / `inactive_connections` / `health_status` 都是"当前值"语义，每周期覆盖即可，无需基准。

### 4. Collector 仅在 daemon 模式启动，支持动态起停

`Server.RunOnce()`（一次性 reconcile）不启动 collector，因为：

- `once` 模式进程秒级退出，采集没有窗口
- Counter delta 需要至少一次基准快照才有意义

`syncTrafficCollector` 中：`s.collector == nil && !cfg.Global.IsMetricsEnabled()` 时直接返回，不构造。

当 `metrics_enabled` 在热加载中从 `true` 切换为 `false` 时，`syncTrafficCollector` 会调用 `s.collector.Stop()` 并将 `s.collector` 置为 `nil`，确保已运行的 collector 被正确停止。反向（`false` → `true`）同样支持：下次调用时检测到 `s.collector == nil` 且 `IsMetricsEnabled() == true`，重新创建并启动 collector。

### 5. 配置热加载

`Collector.UpdateConfig(services, globalCfg)` 在锁内更新内部字段；`run()` 循环每次 tick 检测 `interval` 变化并 `ticker.Reset()`。新增 / 删除 service 通过 `buildServiceConfigMap` 在每次 `updateMetrics` 中重建查表，自动适配。

在 `Server` 的主循环中，config change 事件触发 `s.syncTrafficCollector(newCfg)` 将最新配置推送给已运行的 collector。

### 6. 指标删除（避免标签泄漏）

`pkg/metrics/metrics.go` 提供 `DeleteServiceMetrics` / `DeleteBackendMetrics` / `DeleteBackendHealthMetrics`，用于清理已移除的 service/backend 的 Prometheus label series。

调用点：

- **Reconciler 删除 service 时**：`Reconcile()` 删除不在期望状态中的 service 后，从 `managed` map 取出 `managedServiceInfo`（含 name/listen/protocol/backends），调用 `DeleteServiceMetrics` 清理 service 指标，遍历 backends 调用 `DeleteBackendMetrics` 清理 backend 指标。`managed` map 类型为 `map[ServiceKey]*managedServiceInfo`，存储完整的 config 元数据用于指标清理。
- **Reconciler 删除 destination 时**：`reconcileDestinations()` 删除不在期望状态中的 backend 后，调用 `DeleteBackendMetrics(serviceName, backendAddr, protocol)` 清理该 backend 的所有指标。
- **健康指标清理**：`updateHealthMetrics()` 通过 `prevHealthBackends` 追踪机制，对比前后 backend 集合差集，对已移除 backend 调用 `DeleteBackendHealthMetrics(service, backend)` 清理残留的 health gauge。

### 7. 控制面 Counter 直接 Inc

- `ezlb_config_reload_total`：`Server.Run()` 中通过 `s.configMgr.SetOnReloadCallback(func() { metrics.IncConfigReload() })` 注册回调，配置热重载成功时触发
- `ezlb_reconcile_errors_total`：`lvs.Reconciler.Reconcile()` 在 reconcile 出错时直接调用 `metrics.IncReconcileErrors()`（每个错误累加一次）

这两个不走 collector。

### 8. 健康检查指标独立路径

`healthcheck.Manager` 的 onChange 回调触发 `server.Server.updateHealthMetrics()`，该方法遍历所有 backend 状态并调用 `metrics.SetBackendHealth(serviceName, address, healthy)`。逻辑上属于"事件驱动"而非"周期采集"，与 collector 解耦。

`updateHealthMetrics` 维护 `prevHealthBackends` 集合追踪上一次更新的 backend 列表。每次调用时对比当前集合与历史集合，对已不存在的 backend 调用 `DeleteBackendHealthMetrics` 清理残留 gauge，防止标签泄漏。
